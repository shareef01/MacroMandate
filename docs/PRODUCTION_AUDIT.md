# MacroMandate production audit

**16 November 2026 · Verdict: NOT READY**

The audit started from Git commit `28a05b7e61543c348cd968eee763a21dcaea8ba2` plus the existing local changes. The local changes included an unfinished Paging conversion, ZIP archive support, a camera staging area, and a draft evidence test. Findings below distinguish behavior in that starting tree from behavior after remediation. Existing changes were incorporated in place. The patch is left in the working tree so it can be reviewed alongside the changes that were already there.

The release channel is GitHub Releases. The release APK is signed and passed a device startup smoke test. Live validation with the configured AI provider and representative storage providers remains open. The HUD's Android runtime limits still apply to sideloaded builds. The Play foreground-service declaration and API 37 location-button findings are retained for reference. Earlier builds that use undocumented database versions need a schema before they can be given a safe upgrade path.

## Architecture and data flow

- [MainActivity.kt](../app/src/main/java/com/sharek/macromandate/MainActivity.kt) hosts the Compose navigation graph for Today, Trends, Settings, and meal detail. Compliance state can show the leniency or reinstatement screens. The Android ViewModel coordinates meal mutations and requests. Room is the source of truth for meal names, nutrition totals, flags, stored photo URIs, and audit events. DataStore holds preferences and the Android KeyStore protects newly saved credentials.
- [CameraCaptureScreen.kt](../app/src/main/java/com/sharek/macromandate/ui/CameraCaptureScreen.kt) writes live captures to a cache staging directory. The system photo picker supplies selected images. The analysis path decodes a sampled image, optionally watermarks the live capture with coordinates, and sends a JPEG representation to the configured inference endpoint. The original bytes are copied into private durable storage. The meal row references that local file. Barcode lookup goes separately to Open Food Facts. Manual entry writes directly to Room.
- [DossierExporter.kt](../app/src/main/java/com/sharek/macromandate/util/DossierExporter.kt) writes CSV and ZIP using the Storage Access Framework. ZIP v2 contains meal metadata and original photo bytes. The restore path validates archive structure, identifiers, lengths, and CRCs, writes new files under app-controlled names, then inserts the batch atomically. A mutation lock coordinates backup, restore, photo saves, and deletion. A deletion journal lets the app finish filesystem cleanup after a committed database deletion.
- [MandateApplication.kt](../app/src/main/java/com/sharek/macromandate/MandateApplication.kt) observes the enforcement preference and updates one unique periodic WorkManager job. The worker reads Room and checks the preference before posting a reminder. The Glance widget reads daily data for launcher rendering. A separate foreground service observes daily totals and publishes the ongoing HUD notification.
- Room schemas 6 and 7 are checked in. The original v1 DDL is reconstructible from Git. AGP 9.3.1 and Gradle 9.5.0 target API 37 and support API 29 onward. The verified toolchain uses built-in Kotlin, KSP2, and Room 2.8.4. The release build enables R8 and resource shrinking. Release BuildConfig uses an empty token. The checkout began without a tracked GitHub Actions workflow.

### Security and scope checks

- The launch activity is exported for launcher access. The foreground service is private. The boot receiver checks the protected boot action. The widget receiver is exported for the widget integration. No source-level component was found that exposes meal reads or filesystem writes to an arbitrary intent. Host widget and merged-manifest permission behavior still need device validation.
- The app uses a normal HTTPS client and location defaults off. Only a live capture with location enabled can attach coordinates through the analysis pipeline. Data extraction rules exclude private root, databases, shared preferences, and external directory for system backup and transfer. The manifest explicitly disables app backup and cleartext. User-created ZIPs can contain dietary records, precise locations, and original images. The selected SAF destination controls sharing and retention.
- Release BuildConfig is designed to omit the credential. Debug retains the explicitly configured local fallback for development. The audited debug build had no local fallback key configured. Endpoint credentials embedded in a URL are rejected.
- The dependency audit queried OSV for Maven coordinates resolved on `releaseRuntimeClasspath`. It checks reported vulnerabilities as of the audit date. It does not establish transitive code reachability or scan unknown vulnerabilities and embedded native SDK contents. [OSV API](https://google.github.io/osv.dev/api/)

After the local test, a dedicated RSA release key was created outside the repository. ## Remaining release gates

1. Check the signed APK on supported Android versions. Verify that the calorie HUD behaves gracefully under Android foreground-service limits and that permissions and disclosures match photo and optional location uploads. The Play declaration and Play location-button checks are outside the GitHub release scope.
2. Verify a correctly signed and minified release against the real inference backend and intended model, the real barcode API, and representative local and cloud SAF providers. Exercise startup, rotation, camera permission denial, capture, low storage, time changes, and WorkManager across reboot on a device matrix.
3. Confirm which database versions were distributed. The v1 and v6 upgrade paths are implemented and tested together. The code preserves unrecognized databases by failing to open them. Any actual v2–v5 installations require authoritative DDL or upgrade samples and a nondestructive migration.
4. Define numeric input bounds, legacy credential migration, and an explicit metadata-only recovery path for users whose original photos are already gone. Run the new hosted workflow before release promotion.
